# How React Native projects (and by extension Expo projects) are structured?
React native project are structured in to parts:
1. **The app JavaScript:** This is the project that has all the components and logic.
2. **The native project:** Which is the actual project that runs on the device. This project renders the elements we see on the screen, and also, it provides the native libraries to access to native features.

In the folders project, you'll see the JS application and once you ***prebuild*** the project, an android or iOS folder (depending on you prebuilding) will be created. It's in this created folder on which will reside the Native app.

## Why Native projects are not created when you create the project?
This is because expo follows a philosophy called `Continuous Native Generation` or `CNG`.

> CNG is a ***process for building an Expo app where your native projects are generated on-demand from you app.json*** and package.json, similar to how your node_modules are generated from your package.json.

This philosophy follows the DevOps mindset on which encourage the continuous integration of features in the app. 

To make a prebuild you can use the following command:
```
npx expo prebuild
```
or
```
npx expo prebuild [android|ios]
```

Also you can add `--clean` band to re-generate the native project directories.
# Developments build.
A development build is a **debug** build of your app that contains `expo-dev-client` library.

It helps you iterate as quickly as possible and provides a more flexible, reliable, and complete development environment that Expo Go.

You can install any native library and configure or apply changes to a native project using:
- App Config
- Creating a **config plugin.**

You can create a development build:
- Locally (In case of Android platform you need to install **Android Studio*** or ***Xcode*** in case of Apple).
- Using EAS build (Cloud solution).

# Best practices

- You should not include any sensitive information in the app config (with a few exceptions for fields that are filtered out).

![[Pasted image 20260110104255.png]]

- You should avoid importing app.json or app.config.js directly in your JS code, because this will import the entire file rather than a processed version of it. Instead, use Constants.expoCinfig to access the configuration.

- If you want to configure a build use `config plugins`, in this way, when execute `npx expo prebuild` command, the generated project will contain all the configuration.
